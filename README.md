# 포켓 크리터즈 모바일 v0.3 — 개발 및 서비스 연결 준비 버전

## 현재 상태

이 패키지는 완성된 모바일 설치 파일이 아닙니다. Android 앱 소스, iPhone 앱 소스, 모바일 게임, 실제 계정 서버와 배포 파이프라인을 포함합니다. APK/IPA/TestFlight 및 공개 접속 주소는 아직 생성되지 않았습니다. 실제 Android/iPhone 설치와 터치 성능 검증도 미완료입니다.

외부 DNS 연결 실패, 로컬 소켓 통신의 EACCES, Android SDK/JDK/Gradle 및 macOS/Xcode 부재 때문에 이 환경에서는 공개 서버 배포와 네이티브 앱 컴파일을 완료하지 못했습니다. 포함된 테스트는 서버 요청 처리를 프로세스 내부에서 실행합니다. 공개 인터넷/실제 휴대폰 연결을 검증했다는 의미가 아닙니다.

## 이번 변경

- 지렁이 병사의 기어가기, 몸 늘어남과 눌림, 점프 자세, 발사 반동, 시선 변화, 피격 표정, 상황별 말풍선과 이동 먼지.
- 모바일 전장 확대와 병사를 따라가는 카메라.
- 이메일 회원가입, 로그인 유지, 로그아웃, 계정 삭제. 계정별 클라우드 전투 저장/불러오기 및 다른 기기의 변경 충돌 방지.
- 새 게임 버전 감지, 전투 중 자동 교체 방지, 업데이트 파일 SHA-256 검증, 오류 시 기존 캐시 유지.
- Android/iPhone 네이티브 셸 및 HTTPS에서 홈 화면 설치형 게임 구성.
- 실제 설치 파일 존재 여부에 따라 다운로드 버튼을 표시하는 `/install.html`.

## 체험

`Pocket_Critters_Preview.html`을 PC 브라우저에서 열면 게임과 계정 화면을 확인할 수 있습니다. 파일 실행에서는 회원가입·로그인이 작동하지 않으며 서버 미연결로 표시됩니다. 파일 실행은 모바일 설치를 대체하지 않습니다.

Node.js 24 이상에서 `npm start` 후 `http://127.0.0.1:8787`로 접속하면 개발용 계정 서버를 사용할 수 있습니다. 실제 네트워크 통신이 허용된 환경이 필요합니다. 기본 DB는 `server/data/game.sqlite`입니다. 개인 계정·암호·SQLite DB 파일은 소스 저장소에 올리지 마세요.

## 서비스 구조

게임 파일과 계정 API는 동일한 HTTPS 도메인에서 서비스합니다. 별도의 일반 게임 계정 서버이며 ChatGPT 로그인과 연동하지 않습니다. 비밀번호는 scrypt 해시와 무작위 salt로 보관하며 세션 토큰 원문은 DB에 저장하지 않습니다. 쿠키는 HttpOnly/SameSite=Strict, 운영 환경에서는 Secure를 적용합니다. 비밀번호/세션은 브라우저 localStorage에 넣지 않습니다.

준비·행동 단계의 기기 내부 자동 저장은 이전과 같습니다. 클라우드는 사용자가 명시적으로 저장/불러오기 버튼을 누릅니다. 로그인만으로 기기 내부 전투를 서버 전투로 자동 덮어쓰지 않습니다. 다른 기기에서 변경된 클라우드 저장은 revision 비교로 거부됩니다.

이메일 소유 확인, 비밀번호 찾기/재설정, 메일 발송은 미구현입니다. 공개 가입 서비스 운영 전에 메일 서비스 연동과 복구 절차를 추가해야 합니다. 현재는 개발 테스트용 계정을 사용하세요.

## 모바일 설치

1. 계정 서버를 HTTPS 도메인에 먼저 배포합니다.
2. `node configure-mobile.cjs https://실제게임도메인`으로 두 앱의 접속 주소를 설정합니다.
3. Android: `android`를 Android Studio에서 열고 JDK 17 / SDK 35 / Gradle 8.9 환경에서 빌드합니다. `android/build-apk.ps1`도 사용 가능합니다.
4. iPhone: Mac의 Xcode에서 `ios/PocketCritters.xcodeproj`를 열고 Apple 개발자 팀/서명과 앱 아이콘을 설정한 뒤 빌드합니다. 배포는 TestFlight/App Store 등의 Apple 지원 절차를 따릅니다. 앱 심사 통과를 보장하지 않습니다.
5. 네이티브 빌드 전에도 HTTPS에서 Android Chrome 및 iPhone Safari의 홈 화면 설치를 이용할 수 있습니다. 이는 APK/IPA 설치와 다른 방식입니다.

앱은 신뢰하도록 설정한 HTTPS 게임 도메인만 로드하고, 연결에 실패하면 묶음으로 포함된 오프라인 게임으로 돌아갑니다. 서버 주소가 비어 있으면 오프라인 체험 모드입니다. 네이티브 앱의 서버 업데이트 확인은 다음 실행/사용자 동의 후 새로고침 방식이며, 새 브라우저 API·권한·네이티브 기능은 앱 재빌드가 필요합니다. iOS 스토어 배포 후의 기능 변경은 Apple 정책과 심사 범위를 별도로 확인해야 합니다.

## ‘여기서 수정 → 게임에 반영’ 연결

`.github/workflows/deploy.yml`이 main 브랜치 푸시마다 릴리스 준비 → 테스트 → 서버 패키징 → SSH 배포 → 상태 확인을 수행하도록 작성되어 있습니다. 아직 GitHub 저장소와 서버에 연결하지 않았으므로 자동 배포는 활성화되지 않았습니다.

한 번 필요한 연결: GitHub 저장소, Docker/Compose가 설치된 Linux 서버, 실제 도메인 DNS, SSH 배포 사용자/키와 고정된 호스트키. GitHub Actions secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. 서버 `/srv/pocket-critters/production.env`에는 `GAME_DOMAIN=실제도메인`을 둡니다. 앱 데이터는 이름이 고정된 Docker 볼륨에 유지됩니다.

관리형 서버를 쓰려면 포함된 `render.yaml`로 Render에 연결할 수 있습니다. GitHub 커밋마다 Docker 빌드 안에서 릴리스 생성과 테스트를 실행하고, 성공한 게임을 배포하는 구성입니다. 계정 데이터는 `/data` 영구 디스크에 둡니다. 이 설정은 유료 서버/디스크를 사용하므로 서비스 생성 전 실제 요금과 승인이 필요합니다. Render 연결을 실제로 수행하지 않았습니다. Render를 사용하는 경우 별도 VPS SSH용 deploy 워크플로는 실행하지 않도록 비활성화해야 합니다.

네이티브 빌드 워크플로 `.github/workflows/mobile-build.yml`도 포함했습니다. 저장소 변수 `GAME_ORIGIN`에 실제 HTTPS 게임 주소를 넣으면 GitHub 빌드 환경에서 Android 테스트 APK와 iOS 시뮬레이터 앱을 만들도록 작성되어 있습니다. 아직 실행 결과가 없으며 iOS 시뮬레이터 앱은 iPhone 설치용 IPA가 아닙니다. 실제 iPhone 배포는 Apple 서명/배포 설정을 추가해야 합니다.

서버를 연결한 뒤에는 이 채팅에서 수정을 요청하면 코드를 수정·검증하고 연결된 저장소로 반영하는 방식으로 작업할 수 있습니다. 저장소에 푸시된 변경은 배포 파이프라인을 실행합니다. 채팅을 닫은 뒤 에이전트가 계속 코드를 감시하거나 자동으로 수정하는 구조는 아닙니다.

`node release.cjs`는 실제 파일 내용으로 고유 릴리스 ID를 만듭니다. 버전 번호를 깜빡하고 올리지 않아도 내용이 달라지면 새 릴리스로 구분됩니다. 웹 설치형은 모든 파일 해시가 맞는 새 버전을 캐시에 준비한 뒤 사용자 동의 후 교체합니다. 로그인 API와 저장 API는 서비스 워커 캐시에 보관하지 않습니다. 네이티브 셸은 웹 캐시 대신 HTTPS 최신 파일을 다시 받아 실행합니다.

## 운영 배포

`.env.example`과 `compose.yml` 참고. Docker Compose는 Caddy를 통해 HTTPS를 제공하고, Node 계정 서버와 SQLite 영구 볼륨을 연결합니다. 현재 예제는 단일 서버/단일 게임 프로세스를 전제로 합니다. 데이터 백업, 메일 복구, 운영 모니터링과 실제 기기 검증을 완료한 뒤 공개 서비스로 전환하세요. 서버는 비용이 발생할 수 있으며 이 전달물에서 유료 서비스를 생성하거나 결제하지 않았습니다.

## 검증

`npm test`: 게임 엔진 14개 + 계정/권한/삭제 4개 + 업데이트 2개. 상세 결과 `Test_Results.txt`.

별도 실제 Canvas 렌더러 검사: 1440×900 / 844×390 / 390×844. UI DOM 레이아웃, 터치, Android/iOS 컴파일, 스토어 등록과 공개 접속 검증은 완료하지 않았습니다. 렌더 검사에는 @napi-rs/canvas와 sharp가 필요하지만 서버/게임 실행에는 외부 npm 패키지가 필요하지 않습니다.
